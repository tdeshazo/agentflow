# AgentFlow v1alpha3 typed-contract authoring contract

`agentflow.dev/v1alpha3` preserves the v1alpha2 concise dependency model and
adds machine-checkable handoffs. It is the successor API when a workflow needs
an actor to consume a phase result without scraping a final message, guessing
from incidental files, or trusting runtime logs.

The structural authority is the checked-in
[machine-readable executable schema](../../schema/v1alpha3.schema.json),
generated by `workflow.GeneratedSchema` from the strict v1alpha3 decoder.
`agentflow validate` additionally checks producer/consumer references,
read-only audit authority, dependency links, and runtime support before an
actor can run.

v1alpha3 does not change the meaning of v1alpha1 or v1alpha2. It introduces a
new alpha because typed handoffs materially extend the authoring grammar.

## Typed handoffs

Declare a named workspace artifact under `spec.artifacts`, emit it from exactly
one phase with `outputs`, and consume it through a later phase's `inputs`.
Artifacts currently have `type: files` and `persistence: workspace`. Their
`paths` are workspace-relative patterns. After the producer passes its
deterministic phase validation, the runtime records every matched file's path,
content digest, and mode. Before a consumer actor starts, the runtime requires
the producer's durable artifact record and verifies that those identities still
match the workspace.

Declare validation evidence under `spec.evidence` and emit it through
`spec.validation.<name>.produces`. Evidence currently has `type: validation`.
Its durable record identifies the producer phase and the successful named
validation; it is not a cached command result, provider response, or log.

An input is exactly one reference:

```yaml
inputs:
  - artifact: implementation-surface
  - evidence: implementation-accepted
```

Every artifact/evidence input must directly `dependsOn` the phase that emits
the artifact or runs the evidence-producing validation. Missing, altered, or
incompatible inputs fail before the consumer actor runs.

## Typed conditions and read-only audits

`ifEvidence: <name>` runs a phase only when the named dependency evidence is
available. It is a condition on a typed deterministic result, not on an
actor's prose. A false typed condition follows normal skipped-phase semantics.

An audit phase that consumes a handoff must declare `kind: audit` and
`readOnly: true`. Its named or inline actor cannot have `may_commit: true`; the
runtime also rejects any workspace mutation observed after the actor returns.
Read-only audits may emit validation evidence, but cannot emit a workspace
artifact.

Read-only audits are also the simplest parallel fan-out units. With
`spec.execution.maxParallel` greater than one, independent ready audits have
empty write scopes and may execute concurrently in separate quarantine
workspaces. They remain individually validated and accepted, and a downstream
fan-in phase is not ready until every declared audit dependency has an
accepted marker.

## Completion evidence

`spec.completion.evidence` names validation evidence that must have a
compatible durable producer record before final validation and completion can
run. This lets completion cite structured deterministic proof rather than an
unstructured summary.

## Complete example

```yaml
apiVersion: agentflow.dev/v1alpha3
kind: AgentWorkflow
metadata: {name: typed-example}
spec:
  workspace: {allowWrites: [src/**]}
  agents:
    implementer: {runner: codex, model: gpt-5.6-terra}
    auditor: {runner: codex, model: gpt-5.6-luna, may_commit: false}
  validation:
    implementation-quality:
      run: test -f src/result.txt
      produces: [implementation-accepted]
    audit-quality:
      run: test -f src/result.txt
      hard: true
      produces: [audit-accepted]
  artifacts:
    result:
      type: files
      paths: [src/result.txt]
      persistence: workspace
  evidence:
    implementation-accepted: {type: validation}
    audit-accepted: {type: validation}
  phases:
    - id: implement
      actor: implementer
      prompt: Implement the result.
      validation: implementation-quality
      outputs: [result]
    - id: audit
      kind: audit
      actor: auditor
      prompt: Independently audit the verified result without editing it.
      validation: audit-quality
      dependsOn: [implement]
      readOnly: true
      inputs: [{artifact: result}, {evidence: implementation-accepted}]
      ifEvidence: implementation-accepted
  completion:
    validation: audit-quality
    evidence: [audit-accepted]
```

Use `agentflow validate -f workflow.yaml` and
`agentflow plan --expanded -f workflow.yaml`; the expanded plan includes
`typedContracts`, per-phase typed inputs/outputs, read-only status, and
validation evidence producers.
